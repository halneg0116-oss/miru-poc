# miru. PoC v0.2.1

撮る前に、撮りたい写真が見える。背景→完成構図→半透明ガイド→撮影→確認を検証する、端末内処理のWeb試作です。

## v0.2.1の修正（2026-10-23）

背景確定時の固定3:4クロップを廃止しました。カメラ背景は映像全体を保持してJPEG化し、長辺1920px以内へ縮小するだけです。写真選択の場合も従来どおり元の画像領域を保持します。構図表示は保持した背景にCSSの中央cover表示を適用し、構図画像の保存時に選択比率で一度だけクロップします。比率の切替では背景自体を書き換えません。ライブで撮影する最終写真も、その時のカメラ映像から選択比率へ直接一度だけクロップします。

取得時の縮小・JPEG再圧縮による画質変化は残りますが、固定比率への切り抜きで失っていた領域は保持されます。既存UI・画面遷移・人物素材を維持し、バージョン表示のみ更新。背景解析AIや外部への写真送信は追加していません。v0.2の納品フォルダは変更せず、このフォルダを修正版として提供しています。

`npm test`で既存4件と新しいクロップ回帰テスト1件、計5件が成功しました。新しいテストでは1920×1080、1080×1920、4032×3024、3024×4032の映像全体保持、縮小上限、各比率の元領域からの中央切り抜き、4:5への再選択を確認します。Canvasに渡す描画範囲を検証しており、Safari実機のデコード・撮影・保存結果は別途確認が必要です。

## 起動

追加パッケージ・ビルド・Xcode・APIキーは不要。Python 3でこのフォルダを配信します。

```sh
cd /path/to/miru-v0.2.1
python3 -m http.server 8765 --bind 127.0.0.1
```

Macのブラウザで http://localhost:8765 を開いてください。ES Modulesを使用するため、index.htmlの直接ダブルクリックでは起動しません。

### iPhone Safari

iPhoneのlocalhostはiPhone自身です。MacのlocalhostやLANのHTTPアドレスではライブカメラの条件を満たせません。**このフォルダ全体を、信頼された証明書を持つHTTPSの静的配信環境に配置**し、そのURLをSafariで開いてください。写真は配信先に送信しません。外部ライブラリ、解析タグ、写真アップロードAPIもありません。

配信先は未設定・未公開です。自前HTTPSサーバー、または利用中の静的ホスティングを利用できます。外部サービスは実装の必須依存ではありません。信頼済みローカルHTTPS環境がある場合も利用可能です。HTTPで確認する場合は写真選択・標準カメラによる代替フローを使用してください（端末の提供する選択肢に依存）。

### HTTPS公開の具体例：GitHub Pages

GitHubアカウントとリポジトリの管理権限が必要です。以下は標準のgithub.ioドメインを使い、独自ドメイン・サーバー・ビルド環境を用意しない手順です。この手順はアプリと同梱サンプルを公開します。撮影写真を公開する手順ではありません。公開操作自体は今回実施していません。

1. GitHubで新しい公開リポジトリ（例：`miru-poc`）を作成します。公開ソースでよい場合に利用してください。
2. リポジトリの「Add file → Upload files」で、**このフォルダの中身**をルートに配置してコミットします。`index.html`、`styles.css`、`app.js`、`camera.js`、`image.js`、`presets.js`、`assets/scene.jpg`が必要です。`miru-v0.2.1/`という親フォルダごと置かず、ルートにindex.htmlがあることを確認します。個人の写真や撮影結果は追加しません。README・package.json・testsはアプリの配信に必須ではありません。
3. 「Settings → Pages」の「Build and deployment」で「Source: Deploy from a branch」を選択し、`main`ブランチと`/(root)`を指定して保存します。ブランチ名が異なる場合は実際にアップロードしたブランチを選びます。
4. 「Actions」でPagesのデプロイ成功を確認し、Pages設定に表示される公開URLを開きます。例：`https://YOUR-USER.github.io/miru-poc/`。証明書の反映待ちがある場合はしばらく待ちます。「Enforce HTTPS」が有効になっていることを確認します。
5. iPhone Safariでその**HTTPS URL**を開き、画面のバージョンがv0.2.1になっていることを確認します。旧表示のときはページを再読み込みしてください。更新時は変更したファイルを同じ場所にアップロード・コミットし、再デプロイ完了後に確認します。
6. 「カメラで背景を見る」を押してカメラを許可し、下の受け入れ項目を試します。拒否した場合はSafariのページメニューから当該サイトのカメラ設定を見直し、再読み込みします。ブラウザ内ガイドを使えない場合も標準カメラ・写真選択で続行できます。

静的ファイルの配信にGitHub Pagesを使いますが、カメラ映像・選択写真・撮影結果は端末のメモリで処理し、GitHubや写真APIへアップロードしません。「写真を保存」の共有シートでは利用者が保存先を選びます。

公式手順：[サイト作成](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)、[公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)、[HTTPS設定](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https)。

カメラ許可の問い合わせが出たら許可します。拒否した場合は画面内の案内に従ってSafariのサイト設定を変更するか、写真選択で続けます。

## 使い方・実装済み

1. 「カメラで背景を見る」→背景を映す→「この景色でイメージを見る」で背景を確定。標準カメラ撮影・写真選択でも読み込めます。サンプルのままでも体験可能。
2. 背景重視（固定の初期おすすめ）・全身・寄りを切り替え、同じ背景に人物素材を仮配置。背景解析によるおすすめではありません。
3. 投稿4:5・Story9:16・正方形1:1を選択。「プラン画像を保存」で人物素材入りの構図イメージを書き出せます。
4. 「この構図で撮る」で背面カメラを優先して起動。半透明ガイドを表示し、構図切替・ガイドのオン／オフが可能。最初の画面からも通常撮影へスキップできます。
5. シャッター→プレビュー→保存。ガイドは撮影写真に入りません。選択比率で中央トリミングしたJPEGです。
6. 対応端末では保存ボタンからOSの共有シートが開きます。「画像を保存」など端末側の操作で保存を完了してください。キャンセルは正常終了扱い。非対応環境ではダウンロードに切り替えます。プレビューの長押しも利用できます。

標準カメラはブラウザ内ガイドを表示できません。撮影前に構図を覚えて撮影し、取り込んだ写真を選択比率で切り抜いて確認する代替手段です。カメラ許可待ち中でも戻る・標準カメラの操作は可能です。

## 既存実装の調査と変更

添付READMEは復元版・カメラ未実装と記載していますが、ZIP内コードにはカメラ・保存の初期実装がありました。提供コードを基準にしています。資料内の指示を新しい開発要件として扱っていません。

暖色、書体、4画面の流れ、既存の人物SVGとサンプル背景を維持。既存3:4の比率枠をInstagram正方形1:1へ変更しました。

不足していた背景ライブ撮影、撮影中のガイド切替・スキップ、画面と保存の比率一致、共有シート保存、カメラ停止・遅延した権限応答への対応を追加しました。

- `index.html` / `styles.css`: 既存画面とレスポンシブ表示
- `app.js`: 画面遷移・入力・保存の連携。状態は一箇所に集約
- `presets.js`: 人物位置・サイズ・短い案内の共通データ（%単位）
- `camera.js`: 背面優先・許可・ストリーム停止・遅延応答の無効化
- `image.js`: デコード・中央coverクロップ・JPEG出力（長辺最大1920px程度、拡大しない）
- `assets/`: v0.1のサンプル背景。人物素材は表示・構図保存ともHTMLの既存templateを共用
- `tests/`: クロップ整合性とカメラライフサイクルの回帰テスト

ページ離脱・非表示・画面移動ではカメラを停止します。再開時は起動ボタンを押してください。画像はメモリ内のみで保持し、リロードで消えます。保存は明示操作時のみです。

## iPhoneでの受け入れ確認

- HTTPSで背景カメラが背面を映すこと、背景確定・撮影／ライブラリ読込ができること。
- 同じ背景で3構図・3比率を比較でき、全身の頭と足が入ること。
- 左右端に目印を置いた横長の背景を確定し、4:5→9:16→1:1→4:5と切り替えること。1:1で9:16より左右が広く見え、4:5に戻すと元の範囲に戻ること。構図画像の保存も表示と同じ範囲であること。
- 選んだ構図・比率がライブガイドに引き継がれること。
- 撮影中のガイド切替／オフ、通常撮影へのスキップが動くこと。
- 撮影プレビューと保存写真の比率・切り抜きが一致し、ガイドが入らないこと。
- 写真への保存、共有キャンセル、再撮影を試すこと。
- 権限拒否・許可待ちから戻る・標準カメラ・写真選択・アプリ切替後の再起動で操作が続くこと。
- 375px幅程度の縦画面とSafariのツールバー表示時も主要ボタンを操作できること。

## 未実装・残課題

生成AI、背景解析、ポーズ解析、位置判定、自動シャッター、音声、学習、クラウド写真送信、登録・課金は未実装です。人物素材は実写の完成予測ではありません。

- 背面指定は優先リクエストのため、端末のカメラ構成によって選択結果が変わる可能性があります。
- 背景確定後にカメラの向き・距離が変わっても追跡しません。背景の再整列は撮影者が行います。
- 大きな写真はデコード時にメモリを消費。25MB以下に制限しますが、低メモリ端末の実測が必要です。HEICなどの対応形式はブラウザに依存し、読めない場合はJPEGを案内します。
- ガイドは1種類の人物素材で、体形やポーズの追加は今後の検証対象です。
- ブラウザ内の静的アプリのみ納品。HTTPS公開・iPhone実機検証は未実施です。次はHTTPS配信後、上の受け入れ項目をiPhoneで確認してください。
